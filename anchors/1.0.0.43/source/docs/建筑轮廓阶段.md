## 现行处理顺序

1. 用户用 `SD-REGION` 图层的闭合轻量多段线给定支撑；窗口内必须至少有一个有效支撑（至少3顶点）。此图层不表示用户需要自行圈出配筋区。
2. `SD_AUTO_DETAIL` 读取框选建筑范围及插入点。在同一事务中准备图层、提取建筑材料边界、转换坐标并输出。
3. 混凝土填充图案名称包含“钢筋混凝土”，或等于 `CONCRETE`、`AR-CONC`（忽略大小写）时，提取其边界；该分支不限填充图层。`PUB_HATCH` 上的其余材料填充作为非混凝土排除依据。
4. 读取 `WALL` / `COLUMN` 的 `Line` 与轻量多段线直线段，排除与非混凝土边界重合或中点落在非混凝土内部的线。补入混凝土外边界，去除其内部共边和重复线。原建筑文字、尺寸、标高等不直接复制。
5. 以共同基点将轮廓及支撑放大4倍。支撑按用户顶点复制（保留bulge），不做自动裁剪、延伸、补线；实体写入 `S-OTHER-THIN`，ACI7白色，支撑宽0。
6. 每个支撑按其顶点的X/Y外包矩形连接两条对角线。高>2×宽标“楼层梁”，宽>2×高标“楼层板”；其余比例沿用入口的默认文字“楼层梁”。严格等于2倍不满足对应条件。
7. 文字是 `S-TEXT` 上的 `DBText`，高度250；引线是 `S-OTHER-THIN` 上的 `Line`。轮廓及支撑赋角色标记，叉号和引线不赋角色标记。提交事务后结束，此命令不配筋。

## 与纵筋阶段的边界

建筑轮廓识别在 `ArchitecturalOutlineExtractor` 中。`ContourGraph`、`OffsetRebar.CreateOutline` 属于纵筋阶段：它们消费已经放大后的结构线，重建配筋边界、扣除支撑、准备内偏。改建筑材料筛选时先定位本页；改钢筋偏移或支撑开口时定位纵筋阶段。

`Standards`、`GeometryTools`、`OutlineRole`、`SupportClassification` 是共享文件。不得只因某文件出现在建筑轮廓索引里，就认为整文件仅影响建筑轮廓。

## 按代码记录的适用边界

- 现有提取器以直线轮廓为基础。WALL/COLUMN多段线的弧段跳过；Hatch多段线环按顶点连线，未按弧形精确处理。没有在本次归档中扩展曲线能力。
- 交叉窗口选中实体后，不按窗口边界再裁剪整条线；支撑则要求进入支撑窗口选择。并非任意截图的图像识别。
- 填充边界读取的部分异常在现有代码中被忽略；这是一项保留的实现限制，不代表已增加缺失轮廓诊断。将来排查轮廓遗漏可首先检查这些分支。
- 叉号按外包矩形生成，不是任意多边形内裁剪的叉号；文字避让不保证避开全部建筑线。
- 轮廓提取的短线和重复边判断仍有1.0单位等原有容差；纵筋的“一位小数判定”没有全局替换建筑识别容差。
- 仅创建缺失图层，不从参考DWG动态导入所有图层/线型设置。
